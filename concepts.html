Key Concepts

These seven ideas come up again and again when learning about HTTP.

1. Client-Server Model

The client (like a web browser) always starts the conversation by sending a request. The server stores resources and answers each request with a response.

2. Statelessness

Each HTTP request stands on its own. The server does not remember past requests, which keeps HTTP simple. Websites use cookies to remember things like logins.

3. Methods

A method is the verb of a request and tells the server what action to take. GET retrieves data, POST sends data, PUT replaces data, and DELETE removes it.

4. Status Codes

A three-digit number in every response that tells the client what happened. For example, 200 means OK, 301 means the page moved, and 404 means not found.

5. Head-of-Line Blocking

When one slow or lost item holds up everything waiting behind it. This was the main problem with HTTP/1.1 and, at the TCP level, with HTTP/2.

6. Multiplexing

Sending many requests and responses over one connection at the same time by splitting them into small labelled frames. Introduced in HTTP/2.

7. TLS and HTTPS

TLS is the encryption protocol that protects HTTP traffic. HTTP sent inside TLS is called HTTPS, and it keeps data private and proves the server's identity.
